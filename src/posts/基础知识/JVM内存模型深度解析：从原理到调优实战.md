## 二、运行时数据区详解

### 2.1 内存区域划分

| 区域 | 线程共享 | 存储内容 | 异常类型 |
|------|----------|----------|----------|
| 程序计数器 | 私有 | 当前执行指令地址 | 无OOM |
| 虚拟机栈 | 私有 | 栈帧(局部变量表、操作数栈) | StackOverflowError/OOM |
| 本地方法栈 | 私有 | Native方法调用 | StackOverflowError/OOM |
| 堆 | 共享 | 对象实例、数组 | OOM |
| 方法区 | 共享 | 类信息、常量、静态变量 | OOM |

## 三、垃圾回收机制

### 3.1 对象存活判断

**引用计数法：**
- 优点：实现简单，判断效率高
- 缺点：无法解决循环引用问题

**可达性分析：**
- 从GC Roots出发，遍历对象图
- 不可达对象判定为可回收

**GC Roots包括：**
- 虚拟机栈中引用的对象
- 方法区中类静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中JNI引用的对象

### 3.2 垃圾回收算法

| 算法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 标记-清除 | 标记可回收对象后清除 | 简单 | 内存碎片 |
| 标记-复制 | 内存分两块，存活对象复制到另一块 | 无碎片，效率高 | 内存利用率低 |
| 标记-整理 | 标记后将存活对象移到一端 | 无碎片 | 移动成本高 |
| 分代收集 | 新生代用复制，老年代用标记-整理 | 综合优化 | 实现复杂 |

### 3.3 垃圾收集器对比

| 收集器 | 区域 | 算法 | 特点 | 适用场景 |
|--------|------|------|------|----------|
| Serial | 新生代 | 复制 | 单线程，简单高效 | 客户端应用 |
| ParNew | 新生代 | 复制 | 多线程版Serial | 服务端应用 |
| Parallel Scavenge | 新生代 | 复制 | 吞吐量优先 | 后台计算 |
| CMS | 老年代 | 标记-清除 | 低停顿 | 互联网站点 |
| G1 | 全堆 | 分区 | 可预测停顿 | 大内存应用 |
| ZGC | 全堆 | 染色指针 | 超低停顿(亚毫秒) | 超大内存 |

## 四、G1垃圾收集器深度解析

### 4.1 G1核心特性

```
┌─────────────────────────────────────────────────────────────┐
│                    G1 堆结构                                 │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐          │
│  │ Eden│ │ Old │ │Survi│ │Humo │ │Free │ │Free │          │
│  │     │ │     │ │     │ │     │ │     │ │     │          │
│  └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘          │
│                    Region (1-32MB)                          │
└─────────────────────────────────────────────────────────────┘
```

**G1关键特性：**
- 分区(Region)化堆内存
- 可预测的停顿时间模型
- 优先回收垃圾最多的Region
- 支持大内存(TB级)

### 4.2 G1调优参数

```bash
# 启用G1收集器
-XX:+UseG1GC

# 设置堆大小
-Xmx4g -Xms4g

# 设置目标停顿时间(毫秒)
-XX:MaxGCPauseMillis=200

# 设置Region大小(1-32MB，2的幂)
-XX:G1HeapRegionSize=8m

# 设置触发并发标记的堆占用率
-XX:InitiatingHeapOccupancyPercent=45

# 查看G1日志
-XX:+PrintGCDetails -XX:+PrintGCDateStamps
-XX:+PrintGCTimeStamps -Xloggc:/path/to/gc.log
```

## 五、ZGC：下一代垃圾收集器

### 5.1 ZGC核心特性

| 特性 | 说明 |
|------|------|
| 停顿时间 | < 1ms (亚毫秒级) |
| 支持内存 | 8MB - 16TB |
| 吞吐量损失 | < 15% |
| 并发阶段 | 几乎所有阶段都并发执行 |

### 5.2 ZGC工作原理

```
ZGC核心技术创新：

1. 染色指针 (Colored Pointers)
   - 在指针中存储GC状态信息
   - 不需要额外的对象头空间
   - 支持并发标记和转移

2. 读屏障 (Load Barrier)
   - 在对象引用加载时触发
   - 实现并发转移
   - 支持指针自愈(self-healing)

3. 多重映射 (Multi-Mapping)
   - 同一物理内存映射到多个虚拟地址
   - 支持染色指针实现
```

### 5.3 ZGC调优参数

```bash
# 启用ZGC
-XX:+UseZGC

# 设置堆大小
-Xmx16g -Xms16g

# 设置并发线程数
-XX:ConcGCThreads=4

# 启用ZGC日志
-XX:+UnlockDiagnosticVMOptions -XX:+LogCompilation
-XX:LogFile=/path/to/zgc.log
```

## 七、JVM调优实战案例

### 7.1 案例：频繁Full GC

**问题现象：**
- 应用响应变慢，每隔几分钟Full GC一次
- 堆内存占用持续增长

**排查步骤：**

```bash
# 1. 查看GC状态
jstat -gcutil <pid> 1000

# 2. 生成堆转储
jmap -dump:live,format=b,file=heap.hprof <pid>

# 3. 使用MAT分析
# 找到Memory Leak Suspects
# 查看Dominator Tree定位大对象
```

**解决方案：**
- 检查是否有内存泄漏
- 调整堆大小和GC参数
- 优化代码中的大对象分配

### 7.2 调优参数模板

```bash
# 生产环境推荐配置
# 堆大小：物理内存的60-70%
# 新生代：堆的30-40%
# 老年代：堆的60-70%

# G1收集器配置
-XX:+UseG1GC
-Xmx8g -Xms8g
-XX:MaxGCPauseMillis=200
-XX:G1HeapRegionSize=4m
-XX:InitiatingHeapOccupancyPercent=45
-XX:ConcGCThreads=2
-XX:+PrintGCDetails
-XX:+PrintGCDateStamps
-Xloggc:/var/log/app/gc.log
```

## 八、最佳实践

### 8.1 内存优化原则

1. **合理设置堆大小**：避免频繁扩展/收缩堆
2. **选择合适的收集器**：根据应用场景选择
3. **监控GC日志**：定期分析GC行为
4. **避免内存泄漏**：及时释放不再使用的引用

### 8.2 常见问题清单

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| OOM: Java heap space | 堆内存不足 | 增大堆内存/检查内存泄漏 |
| OOM: Metaspace | 元空间不足 | 增大Metaspace/检查类加载 |
| Full GC频繁 | 老年代空间不足 | 调整新生代比例/检查大对象 |
| GC停顿时间长 | 堆过大/对象过多 | 选择G1/ZGC/调优Region大小 |
